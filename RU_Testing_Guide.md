# Руководство по тестированию проекта «Иммерсивные технологии»

Практическая инструкция: как проверить, что всё компилируется, сцены открываются и
каждый улучшенный скрипт работает корректно.

---

## 0. Подготовка окружения

### 0.1 Открытие проекта
1. Unity Hub → **Add** → выберите папку `ImmersiveTech_Labs`.
2. Откройте проект, дождитесь импорта ассетов.
3. **Важно:** если ранее Unity падал с ошибками компиляции — удалите папку `Library/`
   перед открытием, чтобы сбросить кэш после правок скриптов.

### 0.2 Проверка компиляции (первое, что нужно сделать)
1. Откройте **Window → General → Console**.
2. Нажмите **Clear**, затем **File → Save Project** (форсирует рекомпиляцию).
3. **Ожидаемый результат:** в консоли НЕТ красных ошибок (Error).
   Допускаются только информационные сообщения и, возможно, предупреждения (Warning).
4. Если есть красные ошибки — скопируйте их текст, они указывают файл и строку.

> После правок скриптов должно быть **0 ошибок**. Если Unity показывал
> `CS1061`, `CS0019`, `CS0103` по файлам `InteractionSound.cs` /
> `PhysicsForceOnGrab.cs` — они уже исправлены.

### 0.3 Настройка XR для теста без шлема
Проект можно тестировать **без VR-очков** через эмулятор:
1. **Edit → Project Settings → XR Plug-in Management**.
2. Если нет VR-рантайма — снимите галочку **OpenXR** (симулятор продолжит работать).
3. В каждой сцене уже есть объект **XR Device Simulator**.

**Управление симулятором (запомнить!):**

| Клавиша / кнопка | Действие |
|------------------|----------|
| `W A S D` | Перемещение камеры (ходьба) |
| Мышь (зажатая ПКМ) | Поворот взгляда |
| `Tab` | Переключение между левым/правым контроллером |
| `G` | Захват (grab) объекта |
| `ЛКМ` | Select / Activate (нажатие на объекты) |
| `ПКМ` | Активация UI / взаимодействие |
| `Q` / `E` | Поворот контроллером |
| `Space` + мышь | Приближение/отдаление (near-far) |

Полный список — в окне **XR Device Simulator** во время Play.

### 0.4 Открытие нужной сцены
- `File → Open Scene` → `Assets/Labs/Scenes/LabN_*.unity`
- Или `Edit → Build Settings` — все 5 сцен уже там, выберите нужную.
- **Нажмите Play (▶)**.

> **Почему видно только Lab1?** Скрипт
> `Assets/_LabTools/Editor/AutoOpenLabScene.cs` автоматически открывает `Lab1_Setup`
> при старте редактора. Это нормально — остальные сцены открываются вручную.

## 1. Общий smoke-тест (проверить на каждой сцене)

Для каждой из 5 сцен:
1. Открыть сцену → нажать **Play**.
2. **Ожидаемо:** сцена загружается, в консоли нет ошибок, счётчик FPS идёт.
3. Пройтись (WASD), посмотреть вокруг (мышь) — сцена видна, объекты не «висят в воздухе».
4. Остановить Play. В консоли проверить отсутствие **красных** ошибок во время игры.

**Критерий успеха:** 5 сцен × 3 пункта без ошибок.

## 2. ЛР1 — Настройка XR и модель (Lab1_Setup)

**Что проверить:**
1. Открыть `Lab1_Setup` → Play.
2. В иерархии найдите `XR Origin (XR Rig)` — объект игрока присутствует.
3. В сцене видны: пол, стены, стол (модель из Blender `BlenderTable.fbx`).
4. Симулятор работает: `WASD` двигает взгляд.

**Критерий успеха:**
- Игрок (XR Origin) стоит на полу, не проваливается.
- Модель стола импортирована и видна.
- Компоненты XR: `XR Origin`, `Locomotion` (Mediator + провайдеры) в наличии.

## 3. ЛР2 — Локомоция и сообщение (Lab2_Locomotion)

**Что проверить:**

### 3.1 Перемещение
1. Play, зажать `W` — игрок двигается по сцене (Continuous/Dynamic Move).

### 3.2 Телепортация
1. В сцене найдите 4 объекта **Teleport Anchor**.
2. Наведите контроллер (луч) на зону телепортации, нажмите активацию — игрок
   перемещается в якорь.
3. **Ожидаемо:** луч телепортации имеет свой цвет (изменённый цвет луча интерактора).

### 3.3 Кнопка с информационным сообщением (`InfoMessageButton`)
1. Найдите кнопку, к которой привязан скрипт (обычно цилиндр-кнопка).
2. Наведите контроллер и **нажмите** (select).
3. **Ожидаемо:** появляется информационное сообщение (текст/панель).
4. Нажмите ещё раз — сообщение **скрывается** (режим `toggle = true`).

**Параметры скрипта (Inspector → InfoMessageButton):**
- `Toggle` — вкл/выкл залипание (двойное нажатие прячет/показывает).
- `Auto Hide Delay` — если `Toggle = false`, сообщение скроется через N секунд.

**Критерий успеха:** сообщение появляется и исчезает по нажатию, без ошибок в консоли.

## 4. ЛР3 — Интерактивность (Lab3_Interaction)

**Что проверить:**

### 4.1 Захват объектов (Grab)
1. Наведитесь на куб `Grab_Cube*`, нажмите `G`/select — куб захвачен.
2. Переместите, отпустите — куб имеет физику (падает).
3. **Ожидаемо:** Movement Type = **Velocity Tracking**.

### 4.2 Кнопка спавна куба (`SpawnOnSelect`) — ВАЖНО протестировать
1. Найдите кнопку `Spawn_Button` (жёлтый цилиндр слева).
2. Нажмите её несколько раз (5–9 раз).
3. **Ожидаемо:**
   - Каждое нажатие создаёт куб над кнопкой.
   - Куб получает случайный цвет (`Random Color = true`).
   - **Не более 8 кубов** одновременно (`Max Objects = 8`); при превышении
     самый старый удаляется.
4. Проверьте, что **нет ошибки** `Tag: SpawnedCube is not defined`
   (это был баг, теперь исправлен — объекты хранятся в списке, а не по тегу).

**Параметры (Inspector → SpawnOnSelect):**
- `Spawn Size` — размер куба.
- `Max Objects` — лимит (по умолчанию 8).
- `Random Color` — случайный цвет вкл/выкл.
- `Despawn Time` — `0` = кубы живут вечно; `>0` = исчезают через N сек.

### 4.3 Дверь на Hinge Joint + ручка на Fixed Joint
1. Толкните дверь — она вращается вокруг петли (Hinge Joint).
2. Возьмите ручку (Fixed Joint) — проверьте соединение/движение.

**Критерий успеха:** захват, спавн (с лимитом 8) и дверь работают; консоль чистая.

## 5. ЛР5 — Скрипты (Lab5_Scripting) ⭐ главная проверка правок

В сцене 4 объекта, каждый со своим скриптом. Проверяем по очереди.

### 5.1 `Script_ColorOnGrab` → GrabColorChange
1. Захватите серый куб (`G`/select).
2. **Ожидаемо:** куб **плавно** перекрашивается в `Highlight Color` (зелёный),
   а не мгновенно (работает `Transition Speed`).
3. Отпустите.
4. **Ожидаемо:** цвет **плавно** возвращается к `Return Color`.

**Если хочется мгновенно:** снимите `Use Lerp Return` в Inspector.

### 5.2 `Script_SoundOnGrab` → InteractionSound
1. **Наведение:** подведите луч к кубу, не захватывая.
2. **Ожидаемо:** проигрывается звук наведения (`Hover Clip`), если назначен.
3. **Захват:** нажмите `G` — звук захвата (`Grab Clip`, ~660 Гц).
4. **Отпускание:** отпустите — звук (`Release Clip`, ~440 Гц).

**Проверка вариативности:** захватите/отпустите несколько раз — питч звука
немного отличается (диапазон `Min Pitch` … `Max Pitch`).

> Скрипт требует компонент `XRGrabInteractable` (стоит на объекте).
> Звук наведения работает через `XRBaseInteractable`.

### 5.3 `Script_PhysicsOnGrab` → PhysicsForceOnGrab
1. Захватите оранжевый куб (`G`).
2. **Ожидаемо:**
   - Масса меняется на `Mass On Grab` (5).
   - Куб подпрыгивает/смещается — прикладывается сила (`Push Force`)
     в направлении `Push Direction` (по умолчанию вверх).
3. Отпустите куб.
4. **Ожидаемо:** масса **плавно** восстанавливается до исходной
   (скорость `Mass Restore Speed`), а не рывком.

**Проверка в редакторе (до Play):**
- Выделите объект → в Scene View видна голубая окружность + линия вектора силы
  (это `OnDrawGizmosSelected`).

**Если масса должна оставаться большой после отпускания:** снимите `Restore Mass`.

### 5.4 `Script_HoverScale` → HoverScale
1. Наведите луч на фиолетовый куб (не захватывая) — при наличии `XRSimpleInteractable`.
2. **Ожидаемо:** куб **плавно увеличивается** (`Hover Scale` = 1.25×) по кривой.
3. Отведите луч — куб **плавно** возвращается к исходному размеру.

**Критерий для ЛР5:** все 4 объекта реагируют, цвета/масштаб меняются плавно,
звуки играют, масса восстанавливается, консоль без ошибок.

## 6. ЛР6 — Тренажёр (Lab6_Trainer)

**Что проверить:**

### 6.1 Панель управления и последовательность (`TrainerSequence`)
1. В сцене есть кнопки **Button_A (красная)**, **Button_B (синяя)**, **Button_C (жёлтая)**
   и индикаторы **Indicator_A/B/C**, а также **Indicator_Done**.
2. Нажмите кнопки **в правильном порядке: A → B → C**.
3. **Ожидаемо:**
   - После нажатия A — загорается `Indicator_A`.
   - После B — `Indicator_B`.
   - После C — `Indicator_C` и `Indicator_Done`, появляется сообщение
     **«ЗАДАНИЕ ВЫПОЛНЕНО»**.
4. Нажмите кнопки **в неправильном порядке** (например B первым).
5. **Ожидаемо:** прогресс сбрасывается на 0, индикаторы гаснут.

**Важно:** у `IndicatorLight` по умолчанию `Auto Reset = false` и `Blinking = false`,
поэтому индикаторы **не гаснут сами** — это нужно для корректной работы тренажёра.

### 6.2 Зона-триггер (`TriggerZone`)
1. Найдите куб `Trigger_Zone` (слева, `Collider.isTrigger = true`).
2. Подведите контроллер игрока внутрь зоны (пройдитесь WASD в куб).
3. **Ожидаемо:**
   - Куб **плавно** меняет цвет (`Enter Color`, синеватый).
   - Загорается индикатор `Zone_Indicator`.
4. Выйдите из зоны.
5. **Ожидаемо:** цвет **плавно** возвращается к исходному, индикатор гаснет.

### 6.3 (Опционально) Мигание индикатора
Можно проверить ручную настройку: выделите `Indicator_*`, в Inspector включите
`Blinking = true`, задайте `Blink Rate = 2` → при Play индикатор замигает.
`Auto Reset = true` + `Reset Delay` = индикатор сам выключится через N сек.

**Критерий для ЛР6:** последовательность проверяется верно (сброс при ошибке),
сообщение появляется, зона реагирует на вход/выход с плавным цветом.

## 6А. ЛР4 — VR-интерфейс и звук (Lab4_UI, Lab4_Menu)

> Сцены генерируются скриптом. Если их нет — **Tools → Rebuild Lab4 UI Scenes**.

### 6А.1 Lab4_UI — панель управления
1. Открыть `Lab4_UI` → Play. Перед игроком — World Space Canvas с панелью.
2. Навести **луч контроллера** на кнопку **«Красный»** и нажать (**Trigger** = ЛКМ).
3. **Ожидаемо:** куб `Color_Target` (слева) становится красным. «Зелёный»/«Синий» — аналогично.
4. Нажать **«Случайный»** — куб получает случайный цвет.
5. Двинуть **Slider «Оттенок»** — цвет куба плавно меняется по спектру.
6. Переключить **Toggle «Свет»** — точка-свет `UI_Light` включается/выключается.
7. **Звук:** при каждом нажатии кнопки слышен короткий щелчок (тон 880 Гц).

**Критерий:** кнопки нажимаются лучом (нужен `Tracked Device Graphic Raycaster` на Canvas + `XRUIInputModule` в сцене — они уже есть), цвет/свет/звук работают.

### 6А.2 Lab4_Menu — главное меню
1. Открыть `Lab4_Menu` → Play. Видно меню: **ЗАПУСТИТЬ / ОПЦИИ / ВЫХОД**.
2. Навести луч на **«ЗАПУСТИТЬ»** → нажать.
3. **Ожидаемо:** загружается сцена **Lab4_UI** (обе должны быть в Build Settings).
4. Вернуться в меню (File → Open Scene → Lab4_Menu). Навести луч на **«ОПЦИИ»** → нажать.
5. **Ожидаемо:** появляется панель `Options_Panel` с Toggle «Звук интерфейса» и Slider «Громкость».
6. Toggle выключает звук (mute), Slider меняет общую громкость (`AudioListener`).
7. Кнопка **«НАЗАД»** закрывает панель. **«ВЫХОД»** останавливает Play (в редакторе) / закрывает приложение (в сборке).

**Критерий для ЛР4:** UI интерактивен через контроллеры, кнопки меняют состояние объектов,
меню переключает/загружает сцены, есть звук при выборе элементов.

## 9. Типовая диагностика проблем

| Симптом | Причина | Решение |
|---------|---------|---------|
| Красные ошибки при старте | Компиляция скриптов | Удалить `Library/`, переоткрыть проект |
| `Tag: SpawnedCube is not defined` | Старая версия скрипта | Обновлён — переимпортируйте скрипты |
| Play не запускается | OpenXR без рантайма | Снять галочку OpenXR в XR Plug-in Management |
| Контроллеры не двигаются | Симулятор не активен | Проверить объект `XR Device Simulator`, `Tab` |
| Звука нет | Не назначен AudioClip или нет AudioListener | Проверить `Grab Clip` и наличие AudioListener на XR Origin |
| Объект не хватается | Нет `XRGrabInteractable` / коллайдера | Проверить компоненты в Inspector |
| Индикаторы в ЛР6 гаснут сами | `Auto Reset = true` | Снять галочку `Auto Reset` |
| Видно только Lab1 | Авто-открытие первой сцены | Открыть нужную сцену вручную |
